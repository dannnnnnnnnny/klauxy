# Anthropic Translation Proxy Design

## Goal

Replace terminal input rewriting with a loopback-only Anthropic API proxy. Pressing Enter must submit to the real Claude Code process immediately. Before Claude Code's request reaches Anthropic, KAgent translates only the newly submitted Korean user text through local oMLX and forwards the otherwise unchanged request.

## Scope

KAgent installs a persistent HTTP server bound to `127.0.0.1:18789` and routes Claude through it using the user `settings.json`. A macOS LaunchAgent owns the proxy lifecycle so foreground sessions, Claude's background daemon, and its workers share the same endpoint. Any previous Claude `ANTHROPIC_BASE_URL` is preserved as KAgent's upstream and restored safely on uninstall.

The PTY remains only to preserve Claude Code's normal interactive terminal behavior. KAgent will no longer inspect terminal screen contents, delay Enter, clear input, retype translated text, or display its own translation indicator. Claude Code's normal working state will therefore appear as soon as Enter is pressed.

This first version targets Claude Code's direct Anthropic API transport. It does not implement TLS interception or a general-purpose HTTP proxy.

## Feasibility Probe

Before changing production flow, a local fake upstream will capture only redacted request metadata from a harmless non-interactive Claude invocation. The probe must establish:

- which paths Claude Code calls, including `/v1/messages` and token-counting variants;
- whether streaming is requested and which request/response headers are required;
- whether a usable authentication header is sent when `ANTHROPIC_BASE_URL` points to loopback;
- the message body shapes Claude Code currently emits;
- whether custom-base-URL behavior requires any additional Claude environment setting.

The probe must never print or persist credential values. If Claude Code does not supply credentials to a custom base URL, implementation stops and reports that blocker; KAgent will not install a local CA or intercept TLS without a separately approved design.

## Request Flow

1. The KAgent LaunchAgent keeps a loopback proxy running at `127.0.0.1:18789`.
2. Installation sets Claude's user `env.ANTHROPIC_BASE_URL` to that stable URL. The shim also supplies it to the foreground process.
3. Claude Code accepts terminal input normally and sends an Anthropic request to KAgent.
4. For an eligible Messages API request, KAgent reads and validates the JSON body, locates the newest eligible user-authored text, and consults the current `kagent on/off` state.
5. If enabled and Korean is present, KAgent protects literals with the existing placeholder pipeline, translates through oMLX, validates the result, and substitutes only that text block.
6. KAgent forwards the request to the configured Anthropic upstream and streams the response back without buffering or semantic changes.
7. The proxy remains alive when a foreground launcher exits so background workers can continue using it.

All other paths, methods, bodies, and responses are passed through. URL path and query, status code, status text, streaming chunks, and relevant headers are preserved. Hop-by-hop headers and `Host`/content-length headers are regenerated by the HTTP client as necessary.

## Selecting Text to Translate

The proxy mutates at most one logical user turn per request. It scans `messages` from the end for the nearest `role: user` message because Claude Code 2.1.246 appends an internal `role: system` message after the human turn. Within that user message it considers text content blocks and leaves every non-text block byte-for-byte equivalent at the JSON level. If any later user message or the selected user message contains a `tool_result`, the request is not translated.

Eligible text must contain Korean natural language. The following are not translated:

- assistant messages and all earlier conversation turns;
- `tool_result` content and any nested tool output, even when Korean appears inside it;
- image, document, thinking, tool-use, or unknown content-block types;
- messages with no Korean;
- recognized raw-control inputs already exempted by the current pipeline, such as slash commands and shell commands;
- text that consists only of code, paths, URLs, identifiers, or other protected literals.

When a final user turn contains several eligible text blocks, they are protected and translated as one logical prompt with internal sentinels, then restored into the same number and order of blocks. This preserves their separation while avoiding inconsistent independent translations. If the block mapping cannot be validated exactly, the original request is used.

To prevent retranslating history, KAgent only examines the nearest user message and never rewrites earlier user messages. Tool-result follow-up requests pass through unchanged because their nearest user content contains a tool result. Claude Code's trailing internal system message is preserved.

## Upstream and Authentication

KAgent preserves an existing Claude or shell `ANTHROPIC_BASE_URL` as its upstream; otherwise it uses a reachable local Headroom gateway at `127.0.0.1:8787`, then falls back to `https://api.anthropic.com`. It rejects an upstream matching its own loopback listener to prevent recursion.

Authorization and Anthropic version/beta headers received from Claude Code are forwarded in memory and never logged. KAgent does not read Claude credential files, mint credentials, or store tokens. Diagnostic output may report that an authorization header was present and name its header, but never include its value.

The proxy binds only to `127.0.0.1:18789` and is kept alive by a user LaunchAgent. Request bodies are not logged. Translation history stores the selected original and forwarded text only after upstream accepts the request; credentials and responses are never stored.

## Failure Behavior

Translation remains fail-open. If oMLX is unavailable, times out, returns an invalid translation, invents placeholders, or block reconstruction fails, KAgent forwards the exact original request body to Anthropic. It must not partially mutate a request.

Upstream failures are not hidden or converted: KAgent returns the upstream status, headers, and body to Claude Code. A malformed Messages request that cannot be safely inspected is proxied unchanged. Network or proxy-internal failures before an upstream response use an HTTP error response suitable for Claude Code and emit a concise local diagnostic without secrets or prompt content.

The proxy applies body-size and translation-time limits. It does not retry a translated Anthropic request because an automatic retry could duplicate agent work. Normal retry behavior remains Claude Code's responsibility.

## Components

- `anthropic-proxy`: owns the loopback HTTP server, upstream forwarding, header filtering, abort propagation, and response streaming.
- `message-transform`: parses supported Messages bodies, selects eligible final-user text blocks, invokes the existing translation pipeline, and performs all-or-nothing reconstruction.
- `proxy-service`: installs and manages the user LaunchAgent and stable loopback endpoint.
- `claude-settings`: installs Claude background-worker routing while backing up and conditionally restoring the previous upstream.
- `runClaude`: waits for the persistent proxy, injects its stable URL into the foreground child, and preserves the PTY transparently.
- existing `pipeline`, `translation`, `omlx`, `config`, and `state` modules: continue to own language detection, literal protection, translation, validation, and runtime enablement.

After migration, terminal-screen parsing modules and their dependencies can be removed when no remaining behavior depends on them. Removal happens in the same change only after proxy integration tests pass.

## Tests and Acceptance Criteria

Unit tests will cover final-message selection, content-block eligibility, Korean detection, literal preservation, multi-block reconstruction, invented-placeholder rejection/repair policy, disabled state, malformed/unknown payload pass-through, and all-or-nothing fail-open behavior.

Proxy integration tests will use local fake oMLX and Anthropic servers to verify:

- eligible Korean reaches upstream as English while preceding messages and non-text blocks remain unchanged;
- English, commands, tool results, and disabled-state requests are identical upstream;
- authentication, beta/version, path, and query metadata are forwarded without logging values;
- SSE chunks reach the client incrementally rather than after full buffering;
- client cancellation aborts translation or upstream work;
- oMLX timeout/invalid output sends the original request exactly once;
- upstream error status and body are preserved;
- the server is loopback-only and remains available after a foreground Claude launcher exits.

The existing unit suite, type check, linter, and build must pass. A local Claude smoke test must demonstrate that pressing Enter immediately changes Claude Code to its native processing state and that the fake upstream receives the translated final prompt. A real Anthropic smoke test may be performed only through the user's existing authenticated Claude session and must avoid logging credentials or project content.

## Success Criteria

- Enter is never held for translation and no translated text is retyped into the terminal.
- The upstream agent receives translated English for eligible Korean human prompts.
- Claude Code authentication, streaming, tools, permissions, MCP, thinking, and token counting continue to work.
- Translation failure submits the original Korean prompt without duplicate requests.
- KAgent listens only on loopback and does not persist credentials or prompt bodies.
